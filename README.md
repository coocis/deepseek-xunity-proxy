# DeepSeek XUnity 本机转发器

此程序把 XUnity Auto Translator 的 `CustomTranslate` GET 请求转发给 DeepSeek API。它只监听本机 `127.0.0.1`，API Key 不写入配置文件。

## 文件说明

```text
start-proxy.cmd          一键启动脚本与常用配置
proxy_server.py          Python 3.12 转发器
system_prompt.txt        系统提示词，UTF-8 编码
user_prompt.txt          用户提示词，UTF-8 编码
logs\                    按日期保存的运行日志，自动清理过期文件
failed_translations.jsonl 翻译失败记录，首次失败时自动生成
glossary.json             全局术语表，自动生成，仅保留在本机
glossary_additions.jsonl  自动收录人名的来源记录，仅保留在本机
```

## 首次配置

1. 安装 Python 3.12，并确保命令 `py -3.12 --version` 能正常运行。
2. 在 Windows 的“环境变量”中，新建用户变量：

   ```text
   变量名：DEEPSEEK_API_KEY
   变量值：你的 DeepSeek API Key
   ```

   也可在 PowerShell 执行下列命令，然后重新打开终端或资源管理器：

   ```powershell
   [Environment]::SetEnvironmentVariable('DEEPSEEK_API_KEY', '你的密钥', 'User')
   ```

3. 双击 `start-proxy.cmd`。看到“启动 DeepSeek XUnity 转发器”即表示成功。按 `Ctrl+C` 可停止服务。

API Key 不要写入 `start-proxy.cmd`，也不要上传到网盘、Git 仓库或聊天消息。

## 启动脚本配置

用记事本编辑 `start-proxy.cmd` 顶部的 `set` 行即可。默认值适合日文游戏翻译为简体中文。

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `BIND_HOST` | `127.0.0.1` | 固定为本机地址，不建议改为局域网地址。 |
| `PROXY_PORT` | `8765` | 转发器端口。 |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com` | DeepSeek 的 API 基础地址。 |
| `DEEPSEEK_MODEL` | `deepseek-flash` | 使用的模型名。 |
| `DEEPSEEK_API_KEY_ENV` | `DEEPSEEK_API_KEY` | 保存实际 API Key 的环境变量名。 |
| `REQUEST_TIMEOUT_SECONDS` | `60` | 单次 DeepSeek 请求的超时秒数。 |
| `MAX_INPUT_CHARS` | `200` | 接受的单条原文最大字符数；应与 XUnity 配置保持一致。 |
| `MAX_OUTPUT_TOKENS` | `1000` | 单条译文的最大输出 token 数。 |
| `TEMPERATURE` | `0.1` | 低值使翻译措辞更稳定。 |
| `MAX_RETRIES` | `1` | 单条请求失败后的额外重试次数。 |
| `LOG_LEVEL` | `INFO` | 可选 `DEBUG`、`INFO`、`WARNING`、`ERROR`。 |
| `LOG_TEXT` | `False` | 改为 `True` 才会把原文和译文写入普通运行日志。 |
| `LOG_RETENTION_DAYS` | `2` | 每次启动时清理早于该天数的 `proxy-*.log`。 |
| `GLOSSARY_FILE` | `glossary.json` | 全局人名术语表的本机 JSON 文件路径。 |
| `AUTO_ADD_CHARACTER_NAMES` | `True` | 是否自动收录高置信度角色名。 |
| `NAME_CONFIDENCE_THRESHOLD` | `0.9` | 自动收录的最低模型置信度。 |
| `MAX_NEW_CHARACTER_NAMES` | `3` | 每条原文最多自动收录的人名数量。 |

## 提示词文件

`system_prompt.txt` 和 `user_prompt.txt` 均采用 UTF-8 编码，可自由使用多行中文、标签和特殊符号。

每次请求会依次向模型发送：

1. `system_prompt.txt` 的内容，作为 system message；
2. `user_prompt.txt` 的内容，作为 user message；
3. 语言信息与当前待翻译原文，作为另一条 user message。

不需要在提示词里放 `{text}` 等占位符。

## 全局人名术语表

转发器使用全局 `glossary.json` 保存已确认的人名映射。首次使用可复制 `glossary.example.json` 并改名为 `glossary.json`，或等待转发器自动收录：

```json
{
  "さら": "莎拉",
  "みく": "美玖"
}
```

翻译前，转发器会在本地以最长匹配找出当前句中已有的人名，并遮罩为 `__XU_NAME_数字__`。模型只处理余下文本，返回结果后才恢复为固定中文名；因此不会把整个术语表发送给 API，也不会让不同游戏的无关人名增加 token 消耗。

模型对未遮罩文本返回高置信度角色名候选时，转发器会自动追加到 `glossary.json`，并将来源句、置信度和时间写入 `glossary_additions.jsonl`。两者都是本机运行数据，已由 `.gitignore` 排除，不会被意外推送到公开仓库。

## 配置 XUnity Auto Translator

启动转发器后，编辑游戏目录中的 `BepInEx\config\AutoTranslatorConfig.ini`：

```ini
[Service]
Endpoint=CustomTranslate
FallbackEndpoint=

[General]
Language=zh-CN
FromLanguage=ja

[Custom]
Url=http://127.0.0.1:8765/translate
```

保持 `MaxCharactersPerTranslation=200`，使其与启动脚本的 `MAX_INPUT_CHARS=200` 一致。

注意：若原先使用 `zh-TW`，切换到 `zh-CN` 后 XUnity 会读取 `BepInEx\Translation\zh-CN\Text`。如需沿用既有词库，请手动复制旧目录中的翻译 `.txt` 文件到新目录。

## 失败处理与离线词库

DeepSeek 请求失败时，转发器会：

1. 将原文、语言和错误信息追加到 `failed_translations.jsonl`；
2. 向 XUnity 返回 HTTP 502，而不是返回原文；
3. 游戏因此继续显示原文，XUnity 不会把这条失败结果当作有效译文缓存。

成功返回的译文仍会由 XUnity 自动写入其 `_AutoGeneratedTranslations.txt` 词库。已经命中本地词库的文本不需要经过本转发器，会直接显示。

## Token 用量日志

每条成功的 DeepSeek 响应会在当天的 `logs\\proxy-YYYY-MM-DD.log` 记录本次输入、输出、合计 token，以及本次启动以来的累计 token。例如：

```text
Token 用量：本次 输入=185 输出=42 合计=227；本次启动累计 输入=2310 输出=618 合计=2928
```

累计值只保存在当前转发器进程的内存中，重新启动 `start-proxy.cmd` 后会归零。若 API 响应未提供 `usage` 字段，日志会给出警告且不计入累计；失败请求同样不计入。

## 简单测试

转发器运行时，在 PowerShell 执行：

```powershell
Invoke-WebRequest -UseBasicParsing "http://127.0.0.1:8765/health"
```

返回 `ok` 表示本机服务正在运行。

不要在 `failed_translations.jsonl` 或日志中保存 API Key；本程序也不会记录它。
